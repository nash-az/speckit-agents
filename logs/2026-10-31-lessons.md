# 2026-10-31: lessons

Plugin-generic lessons (project-specific ones go in a project's own `.sdd/learnings.md`).

- **"Waiting on you" must list only what the person can act on now.** The dashboard listed every held
  `[manual]` task of the viewed feature, so the user was asked to "look at the Feedback view" (004 T033) and
  to "start a Job from the Jobs view" (005 T022) before either view existed, and could press I did it or
  Skip on them. Being prompted for something you cannot or need not do yet is confusing (user, 2026-10-31).
  Rule since `fix/waiting-on-you`: a held `[manual]` step is doable once every earlier phase is finished
  (tasks in its own phase do not count, so a setup step mid-phase stays doable); until then it shows in its
  phase as "Not yet" without buttons. When writing tasks, put person checks of built things in a phase after
  the phases that build them.
- **The generic `[manual]` reason misled.** "needs a person to do it (recording, hardware, an account)" was
  shown for every manual task, including checks in a browser. It is now "a step you do yourself; the run
  never attempts it"; the task's own text says what the step is.
- **Pass `--run-args` with `=` when its value starts with `--`.** `sdd-supervise.py --run-args "--no-converge"`
  fails (`argparse` reads the value as an option); use `--run-args=--no-converge`.
- **The launcher still stops at a usage limit.** `bin/sdd-launch.py` passes `--max-wait-hours 0`, so a run
  started from the dashboard stops at the limit and must be restarted by hand. 005's Jobs (`launch_job`, T009)
  wait through resets; for a plain run, start `bin/sdd-supervise.py --max-wait-hours 12` directly.

## 2026-11-01/02

- **"Stop after the current task" during a run's start-up stops before any task (not fixed yet).** Seen
  twice (13:14 and 21:12 on 2026-11-01): Resume, then Stop within ~20 s, logged "safe point: stopping the
  run (no agent running)", and T018 never started. The user expected the task about to start to finish. Cause:
  `bin/sdd-supervise.py` (around the `idle = started == finished` line) counts "no agent running" as a safe
  point even when no agent has started yet in the cycle. Fix: idle is a safe point only once an agent started
  in the cycle; the dashboard says "Starting…" until then.
- **A run cut off before its report showed as "running" forever.** The dashboard treated every run without
  `.sdd/runs/<id>.md` as running, so run `20261031-2039` (cut off at a usage pause, its supervisor later
  ended) showed "running" with T018 running while T018 had committed in the next run. Now a run with no
  report that is not the run in `.sdd/run.json` shows "stopped before its report" and its open tasks
  "interrupted".
- **A held supervisor cannot change its run arguments.** To resume with a task cap, end the held supervisor
  (check it has no child processes and the tree is clean) and start a new one, e.g.
  `sdd-supervise.py --project <repo> "--run-args=--no-converge --max-tasks 1" --max-wait-hours 12 --max-cycles 1`.
  With no `.sdd/run.json` left, this starts a new run id.
- **Run detail lists tasks newest first,** so the running task is on top (user, 2026-11-02).
