# Lessons, 2026-11-02 (later session)

Plugin-generic lessons from running and redesigning speckit-agents today. Project-specific notes would go in the
project's `.sdd/learnings.md`; there were none.

## Run state and the dashboard
- **A dead supervisor's `status.json` decided the state.** Rule 3 of `current_run()` read any `status.json` whose
  state was not `stopped`. A finished supervised run leaves `state: "done"`, so a later `/sdd-run` in a session
  showed **Paused** (banner, Overview, task chips) while it was working. Fixed in `c11294d`: the file counts only
  while its supervisor's pid is alive. Lesson: read run state from what every launch path writes (`run.json` and
  the journal), and use a supervisor's file only as an overlay while that supervisor is alive.
- **Preflight shows nothing.** For about 3 minutes (the full test suite, the plan, the branch) a run exists and
  Start run says "a run is active", but no agent is running, so "Running now" is empty. Planned as a **Preparing**
  state in 008 (on hold, approved in principle).
- **The task log goes blank after a resume, and shows the implementer while the verifier works.** `run_events()`
  (in `bin/sdd-tasks.py`) emits an event when implement, evaluate or repair agents start, never when verify or commit
  start. `task_log()` picks the task's newest event with an agent in the last workflow. Agreed fix (on hold): append
  every agent of the task across all of the run's workflows, with a header per agent and its status.

## Stop and resume
- **Runs started from the dashboard could never be resumed.** `sdd-launch.py` starts the supervisor with
  `--max-cycles 1 --max-wait-hours 0`. `hold()` used `--max-wait-hours` as its deadline, so every hold ended at once,
  and a Resume cycle counted toward `--max-cycles`. The stop/resume tests used their own settings and never caught it.
  Fixed in `a56b7fd`: `--max-hold-hours` (24), Resume cycles do not count, and tests launch with the dashboard's
  settings. Lesson: test a feature with the exact arguments its real caller passes.
- **A stop after the last task left a half-open run.** Stop after current task reached a safe point after the last
  commit, held, and Resume could only close the run. Fixed in `a56b7fd`: with nothing runnable left in the run's scope
  (and not a Job or a `--max-tasks` run), the stop is dropped and the run finishes and writes its report. Run
  `20261102-1438` was closed by hand before the fix (report `ae3c161`).
- **The resumed main loop was messy.** On resume it deleted `.sdd/run.json` and rebuilt it, so the dashboard briefly
  showed nothing running, and one compound shell command was refused before it split it. It recovered by itself.
  Worth tightening in the `/sdd-run` skill text (resume without removing the marker).
- **The operator should not launch runs by hand.** I launched with `--max-cycles 2`, which the person's own
  stop/resume used up. The person wants runs started from the dashboard's Start run. Still open: Stop after the
  current task pressed during start-up stops before any task.

## Writing tasks for the runner
- **The parser reads only a task's first line.** A multi-line task reaches the implementer as its first line only,
  and "After T005 and T008" keeps only T005, because a dependency counts only when the word before it is a
  dependency word. Write each task on one line, spell every edge as "after Tnnn, after Tnnn", and put the detail
  in a data-model section the task cites (with a **Tests** list).
- **Put a file path in its own backticks.** `` `bin/sdd-setup.py detect` `` is not seen as a file.
- **A run cannot edit `spec.md` files** (protected paths). A task that does must be `[manual]`.
- **A run cannot prove what needs a nested `claude -p`.** The nested sandbox fails inside a run, so such proofs are
  `[manual]`, done from a terminal.

## Review
- **A fresh reviewer for `/speckit-analyze` paid off.** On 008 it found 42 issues, 1 of them critical, that the
  author's own pass had missed, then 15 more after the rewrite. Run analyze before committing tasks, so the tasks
  and all fixes land in one commit.
