## Lessons

- **The 95 % usage threshold was not enforced.** It lives only in `bin/sdd-supervise.py`, and this run was started with
  a direct Workflow call from the session, so no supervisor watched usage. At 14:03 the T009 implementer hit the 5-hour
  limit mid-edit. After the reset the workflow started a second T009 implementer on the half-edited tree, and it
  finished. The dashboard showed "Running: Implementing" the whole time, because the pause state comes from the
  supervisor. **Decision (user, 2026-11-06):** the usage check stays in the supervisor only. `/sdd-run` stays one
  granular cycle, since the supervisor itself runs it each cycle and it must not start its own supervisor. Every run
  is started through the launcher (`bin/sdd-launch.py`, the same path as the dashboard's Start run), never by typing
  `/sdd-run` or calling the workflow directly.
- **Phases ran one after another.** Phase 4 (T008) had no dependencies but ran only after Phases 2 and 3.
- **The Skill tool loaded the workflow, not the `/sdd-run` skill**, and suggested passing the arguments as a string,
  which the workflow refuses. The operator followed SKILL.md by hand.
